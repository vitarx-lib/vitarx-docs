# Props

> **前言**：如果你还不了解基本的组件参数使用，请先阅读[组件参数](/docs/quick-start/widget.html#组件参数)章节，以了解组件参数的基本使用方式。

`Props` 是一个浅层**响应式**对象，它包含了传递给组件的“属性”，就比如 `<UserInfo name="John"/>`，那么 `name` 就是组件参数，它的值就是 `John`。

`Props` 在函数组件和类组件中都是通过第一个参数接收，在类组件基类 `Widget` 的构造函数中会对 `Props` 对象进行私有化存储，
所以你无需在类组件的构造函数中单独去存储它，你完全可以通过 `this.props` 得到它。

## defineProps

`defineProps`(别名：`defineDefaultProps`) API函数用于在组件中定义组件参数的默认值，它接收两个参数：

1. **defaultProps**：默认参数对象，键值对形式，键为参数名，值为参数默认值。
2. **inputProps**?: 组件接收到的`Props`对象，此参数是可选的，是为了给 `tsx` 函数组件提供更好的类型推导。

假设我们有一个 `UserInfo` 组件，它接收两个参数：`name` 和 `gender`，其中 `name` 为必填参数，`gender` 为可选参数，默认值为 `1`。

### 在 `函数组件` 中声明默认值

```tsx
import {defineProps} from 'vitarx'

interface Props {
  name: string
  gender?: number
}
function UserInfo(_props: Props){
  const props = defineProps({
    gender: 1
  })
  // props 类型推导如下：
  // {
  //   gender: string
  // }
  
  // 从上面的类型推导结果可以看出缺少了name属性，
  // 这是因为`defineProps`并不知道组件是如何定义的 Props 接口
  // 所以为了更好的类型推导，我们需要将函数接收的props当做第二参数传递给defineProps
  const props2 = defineProps({
    gender: 1
  }, _props)
  // ✅ props2 类型推导如下：
  // {
  //   name: string
  //   gender: number
  // }

  return <div>{props2.name} - {props2.gender}</div>
}
```

### 在 `class组件` 中声明默认值

```tsx
class UserInfo extends Widget<Props,Required<Props>>{
  constructor(props: Props){
    super(props)
    defineProps({ gender: 1 })
  }
  build(){
    // this.props.gender 会被ts类型推导为 number 类型，这归功于Widget所接收的第二个泛型参数
    return <div>{this.props.name} - {this.props.gender}</div>
  }
}
```

## Props 解构细节

不要解构props，这会破坏组件的响应式，如果你强行解构props，当上层组件更新传递的值时，组件不会重新渲染。

```tsx
import { reactive } from 'vitarx'

function UserInfo({ name, gender }: Props) {
  return <div>{name} - {gender}</div>
}

function App() {
  const userInfo = reactive({
    name: 'John',
    gender: 1
  })
  return <div>
    <UserInfo {...userInfo} />
    {/*当我们点击按钮时，gender会被修改，但是UserInfo组件不会重新渲染，因为它已将props解构，丢失了响应性*/}
    <button onClick={()=>userInfo.gender = 2}>修改性别</button>
  </div>
}
```

## 内置属性

### key

`key` 是一个特殊的属性，它用于给 Vitarx 的虚拟 DOM 算法提供提示，以便在重新渲染时能够识别节点。当列表数据发生变化时（如项目的添加、删除或重新排序），`key` 能够帮助 Vitarx 准确识别哪些元素被修改，从而只更新真正需要更新的组件，而不是重新创建整个列表。这有助于提高渲染性能并避免一些与状态相关的问题。

使用 `key` 的最佳实践是为列表中的每个元素提供一个唯一且稳定的标识符：

```tsx
function TodoList() {
  const todos = reactive([
    { id: 1, text: '学习 Vitarx' },
    { id: 2, text: '创建一个应用' }
  ])
  
  return (
    <ul>
      {todos.map(todo => (
        <li key={todo.id}>{todo.text}</li>
      ))}
    </ul>
  )
}
```

### ref

`ref` 是一个特殊的属性，用于获取组件实例或 HTML 元素的引用。它接受一个由 `refEl` 函数 API 创建的 值代理对象作为参数。通过 `ref` 属性，你可以直接访问组件实例或 DOM 元素，从而进行命令式操作。

```tsx
import { refEl } from 'vitarx'

function MyComponent() {
  // 创建一个 refEl 对象用于引用 HTML 元素
  const inputRef = refEl<HTMLInputElement>()
  
  // 创建一个 refEl 对象用于引用组件实例
  const childComponentRef = refEl<ChildComponent>()
  
  const focusInput = () => {
    // 直接访问 DOM 元素并调用其方法
    inputRef.value?.focus()
  }
  
  const callChildMethod = () => {
    // 直接访问组件实例并调用其方法
    childComponentRef.value?.someMethod()
  }
  
  return (
    <div>
      <input ref={inputRef} type="text" />
      <ChildComponent ref={childComponentRef} />
      <button onClick={focusInput}>聚焦输入框</button>
      <button onClick={callChildMethod}>调用子组件方法</button>
    </div>
  )
}
```

### v-bind

> **注意**：`children` 属性不支持 `v-bind` 快捷绑定。

`v-bind` 是一个特殊的属性，用于批量绑定多个属性到组件或 HTML 元素上。它支持以下两种形式：

1. **对象形式**：传入一个 `Record<string, any>` 类型的对象，对象中的每个键值对都会作为属性绑定到元素上。特殊属性如 `style`、`class` 和 `className` 会与元素原有的值进行合并，而不是替换。
2. **数组形式**：传入一个数组 `[props: Record<string, any>, exclude?: string[]]`，其中：
   - 第一个元素是要绑定的属性对象
   - 第二个元素（可选）是一个字符串数组，指定哪些属性不需要绑定

```tsx
import { reactive } from 'vitarx'

function MyComponent() {
  const userProps = reactive({
    name: 'John',
    age: 30,
    role: 'Admin',
    style: { color: 'red' }
  })
  
  return (
    <div>
      {/* 对象形式：绑定所有属性 */}
      <UserInfo v-bind={userProps} />
      
      {/* 数组形式：排除某些属性 */}
      <AdminInfo v-bind={[userProps, ['role']]} />
      
      {/* style 属性会合并而不是替换 */}
      <div style={{ fontSize: '16px' }} v-bind={userProps}>
        {/* 最终 style 为 { fontSize: '16px', color: 'red' } */}
      </div>
      {/*显式声明的属性权重高于 v-bind*/}
      <AdminInfo age={40} v-bind={userProps} />
    </div>
  )
}
```

### v-html

`v-html` 是一个特殊的属性，用于将 HTML 字符串直接渲染到HTML元素中。它接受一个字符串作为参数，并直接将字符串插入到HTML元素的 DOM 中。

```jsx
function MyComponent() {
  const htmlString = '<p>Hello, <strong>World</strong>!</p>'
  return <div v-html={htmlString} />
}
```

> ⚠️ **安全警告**：使用 `v-html` 渲染用户提供的内容可能导致XSS攻击风险。请确保只渲染可信内容，或对用户输入进行适当的HTML转义处理。

> 💡 **使用场景**：`v-html` 适用于需要渲染富文本内容的场景，如从CMS系统获取的格式化文本、Markdown转HTML等。

## 单向数据流

所有的 props 都遵循着**单向绑定**原则，props 因父组件的更新而变化，props 是浅层只读的，
如果你尝试对它进行修改，Vitarx 会在控制台输出一条 ⚠️ 警告信息（仅在开发模式下会输出）。

### 为什么需要单向数据流

单向数据流是 Vitarx 的核心设计理念之一，它确保了数据的流动方向是可预测的：从父组件流向子组件，而不是反向。这种设计有以下几个重要优势：

1. **可预测性**：当应用出现问题时，可以更容易地追踪数据的来源和变化过程。
2. **组件解耦**：子组件不需要了解父组件的实现细节，只需要知道接收什么 props 并如何渲染。
3. **性能优化**：单向数据流使得状态变化更加可控，有助于 Vitarx 的渲染优化。
4. **避免副作用**：防止子组件意外修改父组件的状态，导致应用中出现难以追踪的 bug。

### 常见的错误用法

```tsx
function Counter(props) {
  // ❌ 错误：直接修改 props
  const increment = () => {
    props.count++; // 这会导致警告，并可能引起意外行为
  }
  
  return (
    <div>
      <p>当前计数: {props.count}</p>
      <button onClick={increment}>增加</button>
    </div>
  )
}
```

### 正确的做法

当你需要修改 props 中的数据时，有两种推荐的方式：

#### 1. 通过事件通知父组件更新

```tsx
function Counter(props) {
  // ✅ 正确：通过回调函数通知父组件更新
  return (
    <div>
      <p>当前计数: {props.count}</p>
      <button onClick={props.onIncrement}>增加</button>
    </div>
  )
}

function App() {
  const [count, setCount] = reactive(0)
  
  return (
    <Counter 
      count={count} 
      onIncrement={() => setCount(count + 1)} 
    />
  )
}
```

#### 2. 使用本地状态派生数据

如果你需要基于 props 进行本地修改，可以在组件内部创建一个本地状态：

```tsx
import { reactive, watch } from 'vitarx'

function UserForm(props) {
  // 基于 props 创建本地状态
  const formData = reactive({
    username: props.user.username
  })
  
  // 当 props 变化时更新本地状态
  watch(() => props.user.username, (newUsername) => {
    formData.username = newUsername
  })
  
  const handleSubmit = () => {
    // 提交时将本地状态传递给父组件
    props.onSubmit(formData)
  }
  
  return (
    <form onSubmit={handleSubmit}>
      <input 
        value={formData.username} 
        onChange={(e) => formData.username = e.target.value} 
      />
      <button type="submit">提交</button>
    </form>
  )
}
```

### 总结

单向数据流是 Vitarx 的重要设计原则，它确保了应用中数据流动的可预测性和可维护性。遵循这一原则，可以帮助你构建更加健壮和可靠的应用。记住：

- Props 是只读的，不要尝试直接修改它们
- 通过回调函数或事件通知父组件更新数据
- 如果需要基于 props 进行本地修改，创建一个本地状态
