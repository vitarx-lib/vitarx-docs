# 不同的路由模式

Vitarx Router 支持三种路由模式：path、hash 和 memory。每种模式都有其特定的使用场景和优势。

## Path 模式

Path 模式是最常见的路由模式，它使用 URL 的路径部分来表示路由。

```ts
import { createRouter } from '@vitarx/router';

const router = createRouter({
  mode: 'path',
  routes: [
    { path: '/home', widget: Home },
    { path: '/about', widget: About }
  ]
});
```

### 特点

- URL 更清晰、更符合直觉
- 对 SEO 更友好

### 注意事项

在使用 Path 模式时，需要在服务端配置重定向，将所有路由请求重定向到入口文件（通常是 index.html）。这是因为当用户直接访问某个路由或刷新页面时，服务器需要返回正确的页面。

以下是一些常见服务器的配置示例：

**Nginx:**
```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

**Apache (.htaccess):**
```apache
<IfModule mod_negotiation.c>
  Options -MultiViews
</IfModule>

<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /
  RewriteRule ^index\.html$ - [L]
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule . /index.html [L]
</IfModule>
```

## Hash 模式

Hash 模式使用 URL 的哈希部分（#）来模拟路由。

```ts
const router = createRouter({
  mode: 'hash',
  routes: [
    { path: '/home', widget: Home },
    { path: '/about', widget: About }
  ]
});
```

### 特点

- 不需要服务器配置
- 兼容性好
- URL 中带有 # 符号
- 对 SEO 不友好

### 使用场景

- 静态托管的单页应用
- 不需要考虑 SEO 的内部系统
- 需要兼容老旧浏览器的应用

## Memory 模式

Memory 模式完全基于内存，不会改变 URL。

```ts
const router = createRouter({
  mode: 'memory',
  routes: [
    { path: '/home', widget: Home },
    { path: '/about', widget: About }
  ]
});
```

### 特点

- 路由状态完全保存在内存中
- URL 不会改变
- 刷新页面会丢失路由状态

### 使用场景

- 嵌入式应用（如在原生应用的 WebView 中）
- 不需要 URL 导航的特殊场景
- 微前端子应用

## 模式切换注意事项

1. **路由导航**
   - Path 模式：直接通过 URL 路径导航
   - Hash 模式：通过 URL 的哈希部分导航
   - Memory 模式：只能通过编程方式导航

2. **刷新处理**
   - Path 模式：需要服务端支持
   - Hash 模式：自动处理
   - Memory 模式：会丢失路由状态

3. **SEO 考虑**
   - Path 模式：完全支持 SEO
   - Hash 模式：搜索引擎不会处理哈希部分
   - Memory 模式：不支持 SEO

## 最佳实践

1. 如果是正式的生产环境应用，推荐使用 Path 模式
2. 如果是简单的演示项目或静态托管，可以使用 Hash 模式
3. 如果是嵌入式应用或特殊场景，可以考虑 Memory 模式

选择合适的路由模式应该基于以下因素：
- 项目的部署环境
- SEO 需求
- 目标用户的浏览器支持情况
- 是否需要服务端配置
