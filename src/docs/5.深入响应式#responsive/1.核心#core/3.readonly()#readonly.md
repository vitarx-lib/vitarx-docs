# readonly()

## 概述

`readonly()` 函数用于创建一个只读的响应式对象，它会将一个普通对象或响应式对象转换为只读对象。只读对象的所有属性都不可修改，任何修改操作都会在控制台输出警告信息。

```js
import { readonly } from 'vitarx'

const original = { count: 0, user: { name: 'Alice' } }
const state = readonly(original)

// 尝试修改属性会输出警告
state.count++ // 控制台警告：对象是只读的，不可修改count属性！
state.user.name = 'Bob' // 控制台警告：对象是只读的，不可修改name属性！
```

## 类型定义

```ts
// 深层只读（默认）
function readonly<T extends AnyObject>(target: T): DeepReadonly<T>

// 浅层只读
function shallowReadonly<T extends AnyObject>(target: T): Readonly<T>
```

## 深层只读与浅层只读

`readonly()` 默认创建深层只读对象，这意味着对象的所有嵌套属性都会被转换为只读的：

```js
const state = readonly({
  user: {
    profile: {
      address: {
        city: 'Shanghai'
      }
    }
  }
})

// 深层嵌套属性也是只读的
state.user.profile.address.city = 'Beijing' // 控制台警告
```

如果只需要对象的顶层属性具有只读性，可以使用浅层只读：

```js
import { shallowReadonly } from 'vitarx'

const state = shallowReadonly({
  user: {
    name: 'Alice'
  }
})

state.user = { name: 'Bob' } // 控制台警告，顶层属性不可修改
state.user.name = 'Charlie' // 可以修改，因为嵌套对象不是只读的
```

## 只读对象的特性

### 1. 与响应式对象结合使用

`readonly()` 常用于将响应式对象转换为只读对象，这样可以在不允许修改的场景中安全地传递响应式数据：

```js
import { reactive, readonly } from 'vitarx'

// 创建一个响应式对象
const original = reactive({ count: 0 })

// 创建一个只读版本
const state = readonly(original)

// 通过原始响应式对象修改值
original.count++

// 只读对象会反映这些变化
console.log(state.count) // 1

// 但不能通过只读对象修改值
state.count++ // 控制台警告
```

### 2. 判断对象是否为只读

可以使用 `isReadonly()` 函数判断一个对象是否为只读对象：

```js
import { readonly, isReadonly } from 'vitarx'

const original = { count: 0 }
const state = readonly(original)

console.log(isReadonly(original)) // false
console.log(isReadonly(state)) // true
```

注意：`isReadonly()` 只能判断对象是否为只读对象，不能判断是否为响应式对象。

## 最佳实践

1. 使用 `readonly()` 保护不应被修改的数据。

2. 当需要暴露响应式状态但不希望外部修改时，使用 `readonly()` 包装后再暴露。

3. 对于只需要保护顶层属性的场景，使用 `shallowReadonly()`。
