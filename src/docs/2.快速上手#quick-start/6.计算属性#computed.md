# 计算属性

计算属性是基于响应式依赖进行缓存的特殊值。当依赖的响应式状态发生变化时，计算属性会自动重新计算并更新结果。这使得我们可以声明性地描述一个值依赖于其他值的方式。

## 基础用法

### computed()

我们可以使用 `computed()` 函数来创建一个计算属性。它接受一个 getter 函数作为参数，返回一个只读的响应式 `Computed` 对象。

```js
import { ref, computed } from 'vitarx'

const count = ref(0)

// 创建一个计算属性
const double = computed(() => count.value * 2)

console.log(double.value) // 0

// 修改依赖的响应式状态
count.value = 2

// 计算属性会自动更新
console.log(double.value) // 4
```

与 `ref` 类似，计算属性也需要通过 `.value` 属性来访问计算结果。不同的是，计算属性默认是只读的，尝试修改计算属性的值会收到警告。

## 可写计算属性

### 使用 setter 选项

如果需要创建一个可写的计算属性，可以提供一个带有 `getter` 和 `setter` 的选项对象：

```js
import { ref, computed } from 'vitarx'

const count = ref(0)

// 创建一个可写的计算属性
const double = computed(
  // getter
  () => count.value * 2,
  {
    // setter
    setter: (newValue) => {
      // 注意：这里我们修改的是依赖的值，而不是计算属性本身
      count.value = newValue / 2
    }
  }
)

console.log(double.value) // 0
double.value = 10
console.log(count.value) // 5
console.log(double.value) // 10
```

## 计算属性选项

### 惰性计算

默认情况下，计算属性是惰性的，只有在首次访问 `.value` 时才会执行计算。如果希望在创建计算属性时就立即计算结果，可以设置 `lazy` 选项为 `false`：

```js
const immediateComputed = computed(() => expensiveOperation(), {
  lazy: false // 立即计算，而不是等到首次访问 .value 时
})
```

### 自动销毁

默认情况下，计算属性会随着作用域的销毁而自动销毁。如果希望计算属性在作用域销毁时保持活跃，可以设置 `autoDestroy` 选项为 `false`：

```js
const persistentComputed = computed(() => someComputation(), {
  autoDestroy: false // 作用域销毁时不会自动销毁
})
```

也可以使用链式调用方式设置：

```js
const persistentComputed = computed(() => someComputation())
  .autoDestroy(false)
```

通常用于避免全局共享的计算属性被组件作用域销毁，在组件中访问一个全局计算属性时，如果计算属性是首次被访问，则会被组件作用域错误的捕获并管理，从而导致计算属性的销毁。

## 在组件中使用

计算属性在组件中特别有用，可以根据组件的状态派生出新的值：

```jsx
import { ref, computed } from 'vitarx'

function TodoList() {
  const todos = ref([
    { text: '学习 Vitarx', completed: true },
    { text: '构建应用', completed: false }
  ])
  
  // 创建一个计算属性，用于过滤已完成的任务
  const completedTodos = computed(() => {
    return todos.value.filter(todo => todo.completed)
  })
  
  return (
    <div>
      <h1>待办事项</h1>
      <div>完成进度: {completedTodos.value.length} / {todos.value.length}</div>
      <ul>
        {todos.value.map((todo, index) => (
          <li key={index}>
            <input 
              type="checkbox" 
              checked={todo.completed}
              onChange={() => {
                todo.completed = !todo.completed
              }}
            />
            {todo.text}
          </li>
        ))}
      </ul>
    </div>
  )
}
```

## 最佳实践

### 避免直接修改计算属性

计算属性的值应该是通过其依赖派生出来的，不应该直接修改计算属性的值。如果需要修改，应该修改其依赖的响应式状态。

### 保持计算函数的纯净

计算函数应该是纯函数，不应该有副作用（如修改全局状态或执行异步操作）。这样可以确保计算属性的可预测性和可测试性。
