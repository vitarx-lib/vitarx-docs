# computed()

## 概述

computed()是一个用于创建计算属性的函数。计算属性是基于其响应式依赖进行缓存的值，只有当依赖项发生变化时才会重新计算。这使得我们可以声明性地创建派生状态，避免重复计算，提高应用性能。

## 类型定义

```ts
function computed<T>(getter: () => T, options?: ComputedOptions): Computed<T>

interface ComputedOptions {
  lazy?: boolean
  setter?: (newValue: T) => void
  autoDestroy?: boolean
}

interface Computed<T> {
  readonly value: T
}
```

## 基础用法

### 创建计算属性

```js
import { ref, computed } from 'vitarx'

const count = ref(0)
const double = computed(() => count.value * 2)

console.log(double.value) // 0
count.value = 2
console.log(double.value) // 4
```

### 计算属性的特性

1. **只读性**：计算属性默认是只读的，不能直接修改计算属性的值
2. **缓存机制**：计算结果会被缓存，只有当依赖发生变化时才会重新计算
3. **惰性求值**：只有在访问计算属性的`.value`时才会执行计算

## 配置选项

### lazy

通过`lazy`选项可以控制计算属性的计算时机：

```js
const immediateComputed = computed(() => expensiveOperation(), {
  lazy: false // 创建时立即计算，而不是等到访问.value时
})
```

### setter

通过`setter`选项可以创建可写的计算属性：

```js
const count = ref(0)
const double = computed(
  () => count.value * 2,
  {
    setter: (newValue) => {
      // 在setter中修改依赖值，而不是直接修改计算属性
      count.value = newValue / 2
    }
  }
)

console.log(double.value) // 0
double.value = 10 // 通过setter修改
console.log(count.value) // 5
console.log(double.value) // 10
```

### autoDestroy

通过`autoDestroy`选项可以控制计算属性是否随作用域自动销毁：

```js
const double = computed(() => count.value * 2, {
  autoDestroy: false // 不随作用域自动销毁
})
```

默认情况下，计算属性会随着其所在的作用域销毁而销毁。但在某些场景下（如计算属性在局部作用域中初始化，但需要在作用域销毁后继续使用），可以设置`autoDestroy`为`false`来保持计算属性的生命周期。

## 与其他API配合

### 与watch一起使用

可以监听计算属性的变化：

```js
const count = ref(0)
const double = computed(() => count.value * 2)

watch(
  () => double.value,
  (newValue, oldValue) => {
    console.log('double changed:', newValue, oldValue)
  }
)
```

## Computed类方法

### destroy()

用于手动销毁计算属性，销毁后计算属性将不再响应依赖的变化：

```js
import { ref, computed } from 'vitarx'

const count = ref(0)
const double = computed(() => count.value * 2)

// 手动销毁计算属性
double.destroy()

// 销毁后不再响应依赖变化
count.value = 2
console.log(double.value) // 仍然保持最后一次计算的值
```

### stop()

暂停计算属性的依赖追踪，但不销毁计算属性：

```js
import { ref, computed } from 'vitarx'

const count = ref(0)
const double = computed(() => count.value * 2)

// 暂停依赖追踪
double.stop()

// 依赖变化不会触发重新计算
count.value = 2
console.log(double.value) // 保持暂停时的值
```

### init()

手动初始化计算属性的值，通常用于在首次访问`.value`之前预先计算值：

```js
import { ref, computed } from 'vitarx'

const count = ref(0)
const double = computed(() => {
  console.log('computing...')
  return count.value * 2
})

// 手动初始化，会执行一次计算
double.init()

// 由于已经初始化，访问value不会触发重新计算
console.log(double.value) // 0
```

`init()`方法与`lazy`选项的关系：
- 当`lazy: true`（默认值）时，可以使用`init()`在需要时手动触发首次计算
- 当`lazy: false`时，计算属性会在创建时自动初始化，调用`init()`不会产生额外效果

```js
// lazy为false时会立即计算，无需调用init()
const immediateDouble = computed(() => count.value * 2, {
  lazy: false
})

// lazy为true时可以使用init手动控制初始化时机
const lazyDouble = computed(() => count.value * 2)
lazyDouble.init() // 手动初始化
```

### autoDestroy()

动态设置计算属性是否随作用域自动销毁：

```js
import { ref, computed } from 'vitarx'

const count = ref(0)
const double = computed(() => count.value * 2)
  .autoDestroy(false) // 链式调用设置不自动销毁

// 或者后续修改
double.autoDestroy(true) // 设置为自动销毁
```

## API参考

### isComputed

用于判断一个值是否为计算属性：

```js
import { ref, computed, isComputed } from 'vitarx'

const count = ref(0)
const double = computed(() => count.value * 2)

console.log(isComputed(double)) // true
console.log(isComputed(count)) // false
```

### unComputed

用于解除计算属性的监听并获取其当前值：

```js
import { ref, computed, unComputed } from 'vitarx'

const count = ref(0)
const double = computed(() => count.value * 2)

// 停止监听依赖变化，并返回当前值
const value = unComputed(double)
console.log(value) // 当前的计算结果

// 对于非计算属性值，直接返回原值
const plainValue = unComputed(10)
console.log(plainValue) // 10
```

## 最佳实践

1. **保持getter函数的纯粹性**：getter函数应该只做计算工作，不要有副作用
2. **避免直接修改计算属性**：应该修改依赖的响应式状态，而不是计算属性本身
3. **合理使用缓存机制**：对于计算开销较大的操作，优先使用计算属性而不是方法
4. **注意依赖收集**：确保getter函数中访问的所有响应式状态都是必要的依赖

## 注意事项

1. 计算属性的getter函数不应该有副作用（如异步操作或修改其他状态）
2. 避免在计算属性中使用异步操作，如果需要异步数据，考虑使用watch或其他方式
3. 计算属性应该是幂等的，多次访问应该返回相同的结果（除非依赖发生变化）
