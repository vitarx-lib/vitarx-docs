# 路由器配置

路由器配置选项允许你自定义路由的行为和属性。本节将详细介绍每个配置选项的用途和使用方法。

## 基础配置

### base

- **类型**：`string`
- **默认值**：`"/"`

指定路由的基础路径，通常用于在部署时指定子目录。

```ts
const router = createRouter({
  base: '/app',  // 应用部署在 /app 子目录下
  routes: [
    // ...
  ]
})
```

### mode

- **类型**：`'hash' | 'path' | 'memory'`
- **默认值**：`'hash'`

指定路由的历史模式：

- `'hash'`：使用 URL hash 来模拟一个完整的 URL，当 URL 改变时不会重新加载页面
- `'path'`：使用 HTML5 History API，URL 看起来更美观
- `'memory'`：完全基于内存的历史记录，主要用于非浏览器环境

```ts
const router = createRouter({
  mode: 'path',  // 使用 HTML5 History 模式
  routes: [
    // ...
  ]
})
```

### strict

- **类型**：`boolean`
- **默认值**：`false`

是否启用严格模式。在严格模式下，路由匹配将区分大小写。

```ts
const router = createRouter({
  strict: true,  // 启用严格模式
  routes: [
    // '/about' 和 '/About' 将被视为不同的路由
  ]
})
```

## 路由规则

### routes

- **类型**：`Route[]`
- **必填**：是

定义路由规则的数组，每个路由规则描述了路径和对应的组件或其他信息。

```ts
const router = createRouter({
  routes: [
    { path: '/', widget: Home },
    { path: '/about', widget: About },
    { path: '/user/{id}', widget: User },
    {
      path: '/posts',
      widget: PostLayout,
      children: [
        { path: '{id}', widget: PostDetail }
      ]
    }
  ]
})
```

## URL 配置

### suffix

- **类型**：`'*' | string | string[] | false`
- **默认值**：`'*'`

指定路由的后缀匹配规则：

- `'*'`：匹配任何后缀
- `string`：匹配指定后缀
- `string[]`：匹配多个后缀
- `false`：完全匹配路径

```ts
const router = createRouter({
  // 匹配 .html 和 .htm 后缀
  suffix: ['.html', '.htm'],
  routes: [
    // '/about.html' 和 '/about.htm' 都会匹配到该路由
    { path: '/about', widget: About }
  ]
})
```

### defaultSuffix

- **类型**：`string`
- **默认值**：无

指定默认的 URL 后缀。如需使 URL 地址看起来更符合静态网站特征，可以指定一个默认后缀，例如 '.html'。

```ts
const router = createRouter({
  defaultSuffix: '.html',
  routes: [
    // 访问 '/about' 时，URL 会自动变为 '/about.html'
    { path: '/about', widget: About }
  ]
})
```

### pattern

- **类型**：`RegExp`
- **默认值**：`/[\w.]+/`

指定默认的动态路由匹配模式，用于定义复杂的路径匹配规则。

```ts
const router = createRouter({
  // 允许在动态参数中使用中文字符
  pattern: /[\\d]+/,
  routes: [
    // '/user/1' 将被正确匹配
    { path: '/user/{id}', widget: UserProfile }
  ]
})
```

## 滚动行为

### scrollBehavior

- **类型**：`'auto' | 'smooth' | 'instant' | ScrollBehaviorHandler`
- **默认值**：`'auto'`

定义切换页面时的滚动行为。可以是预定义的行为标识符或自定义的处理函数。

```ts
const router = createRouter({
  // 使用平滑滚动
  scrollBehavior: 'smooth',

  // 或者使用自定义处理函数
  scrollBehavior: (to, from, savedPosition) => {
    if (savedPosition) {
      return savedPosition
    }
    return { top: 0, behavior: 'smooth' }
  }
})
```

### anchorsScrollBehavior

- **类型**：`'auto' | 'smooth' | 'instant'`
- **默认值**：`'auto'`

定义锚点跳转时的滚动行为。

```ts
const router = createRouter({
  // 使用平滑滚动效果跳转到锚点
  anchorsScrollBehavior: 'smooth'
})
```

## 导航守卫

### beforeEach

- **类型**：`BeforeEnterCallback`

在每个路由进入之前调用的钩子函数，允许你在路由激活之前执行逻辑检查或重定向。

```ts
const router = createRouter({
  beforeEach: (to, from) => {
    // 检查用户是否已登录
    if (to.index !== '/login' && !isAuthenticated()) {
      return '/login'
    }
  }
})
```

### afterEach

- **类型**：`AfterEnterCallback`

在每个路由进入之后调用的钩子函数，允许你在路由激活之后执行逻辑，例如页面初始化或统计分析。

```ts
const router = createRouter({
  afterEach: (to, from) => {
    // 记录页面访问
    analytics.logPageView(to.path)
  }
})
```

## 未匹配路由处理

### missing

- **类型**：`RouteWidget`

指定未匹配到路由时要渲染的组件（仅在根 `RouterView` 渲染）。

```ts
const router = createRouter({
  missing: NotFound,  // 404 页面组件
  routes: [
    // ...
  ]
})
```

::: warning 注意
如果你需要在未匹配到路由时重定向到指定的页面，你不应该使用 `missing` 选项，而是应该在路由 `beforeEach` 钩子中判断 `to.matched.length === 0` 时返回重定向目标。

如果你设置了 `missing` 选项，新路由没有匹配时也会更新 URL 地址，然后渲染 `missing` 组件。你可以通过 `useRoute().matched.length` 来判断是否真正匹配到了路由。
:::
