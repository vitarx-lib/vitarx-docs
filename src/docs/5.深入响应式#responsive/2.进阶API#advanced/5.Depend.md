# Depend

> **前言**：依赖收集器是响应式系统的核心组件之一，它负责追踪和记录响应式数据的使用情况，为后续的响应式更新提供依赖关系信息。

## 基本概念

依赖收集器（`Depend`）主要用于收集闭包函数对响应式变量的依赖关系。它能够自动追踪函数执行过程中使用到的所有响应式数据，并建立起数据与使用者之间的关联。

### 核心数据结构

- **依赖集合（Deps）**：一个 `Map` 对象，其中：
  - 键：响应式代理对象
  - 值：该代理对象被引用的属性名集合（`Set<PropName>`）

## 核心功能

### 依赖追踪

```ts
import { track } from 'vitarx'

// 手动追踪依赖
track(proxy, 'propertyName')
```

> **注意**：在大多数情况下，你无需手动调用 `track` 方法，因为依赖会在访问响应式数据时自动收集。只有在使用代理对象本身而不是其属性时，才需要手动追踪。

### 依赖收集

```ts
import { collect } from 'vitarx'

const count = ref(0)
const name = ref('Alice')

// 收集函数依赖
const { result, deps } = collect(() => {
  console.log(`${name.value} clicked ${count.value} times`)
})
```

依赖收集支持两种模式：

1. **共享模式**（默认）：
   - 使用方式：`collect(fn)` 或 `collect(fn, 'all')`
   - 特点：允许多个收集器同时工作，适用于大多数场景

2. **独占模式**：
   - 使用方式：`collect(fn, 'self')`
   - 特点：临时停用其他所有收集器，确保依赖只被当前收集器收集
   - 应用：计算属性等需要精确控制依赖范围的场景

## 工作原理

1. **自动收集**：
   - 当访问响应式对象的属性时，系统会自动调用 `track` 方法记录依赖
   - 收集器会将代理对象和被访问的属性名添加到依赖集合中

2. **多收集器协作**：
   - 共享模式下，多个收集器可以同时工作
   - 独占模式下，临时禁用其他收集器，确保依赖的专属性

## 使用示例

### 基础用法

```ts
import { collect, ref } from 'vitarx'

const user = ref({
  name: 'John',
  age: 30
})

// 收集函数依赖
const { deps } = collect(() => {
  console.log(`${user.value.name} is ${user.value.age} years old`)
})

// deps 中包含了 user 对象及其 name 和 age 属性的依赖信息
```

### 手动追踪示例

```ts
import { track, reactive } from 'vitarx'

const state = reactive({
  list: [1, 2, 3]
})

// 当需要追踪代理对象本身时
track(state, 'list')
```

## 最佳实践

1. **优先使用自动收集**：
   - 大多数情况下，依赖会自动收集，无需手动干预
   - 只在特殊情况下使用 `track` 方法手动追踪

2. **选择合适的收集模式**：
   - 一般场景使用默认的共享模式
   - 需要精确控制依赖范围时使用独占模式

3. **注意性能优化**：
   - 避免在一个函数中收集过多不必要的依赖
   - 合理使用独占模式避免依赖泄漏
