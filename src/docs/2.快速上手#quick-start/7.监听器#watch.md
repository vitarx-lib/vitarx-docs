# 监听器

监听器允许我们监听响应式数据的变化并执行相应的副作用。Vitarx 提供了一系列侦听函数，使我们能够以不同的方式监听数据变化。

## 基础用法

### watch()

`watch()` 函数是最常用的侦听函数，它可以监听响应式对象的变化或者一个 getter 函数的返回值变化。

```js
import { watch, reactive, ref } from 'vitarx'

// 监听响应式对象
const state = reactive({ count: 0, name: 'Vitarx' })
watch(state, (props, origin) => {
  // props 是变化的属性名数组
  // origin 是被监听的响应式对象
  console.log(`属性 ${props.join(', ')} 发生了变化`)
})

// 修改属性触发侦听回调
state.count++
// 输出: 属性 count 发生了变化

watch(() => state.count, (newValue, oldValue) => {
  // newValue 是新值，oldValue 是旧值
  console.log(`state.count 从 ${oldValue} 变为 ${newValue}`)
})

// 修改值触发侦听回调
state.count++
// 输出: state.count 从 1 变为 2
```

## 高级侦听函数

### watchChanges()

`watchChanges()` 函数可以同时监听多个响应式对象的变化。

```js
import { watchChanges, reactive, ref, microTaskDebouncedCallback } from 'vitarx'

const user = reactive({ name: 'Alice' })
const settings = ref({ theme: 'dark' })

// 监听多个响应式对象
watchChanges([user, settings], (props, origin) => {
  // props 是变化的属性名数组
  // origin 是发生变化的响应式对象
  console.log(`${origin === user ? 'user' : 'settings'} 的 ${props.join(', ')} 属性变化了`)
})

// 修改不同对象的属性会触发多次回调
user.name = 'Bob'
// 输出: user 的 name 属性变化了
settings.value.theme = 'light'
// 输出: settings 的 theme 属性变化了

// 使用微任务防抖函数实现在同一个微任务中只执行一次回调
watchChanges([user, settings], microTaskDebouncedCallback(() => {
  console.log('数据发生了变化')
}))
```

### watchValue()

`watchValue()` 函数用于监听响应式对象的值变化，回调函数接收新值和旧值作为参数。

```js
import { watchValue, reactive } from 'vitarx'

const state = reactive({ count: 0 })

watchValue(state, (newValue, oldValue) => {
  console.log('新值:', newValue)
  console.log('旧值:', oldValue)
})

state.count++
// 输出:
// 新值: { count: 1 }
// 旧值: { count: 0 }
```

> 注意：当监听源对象是值类型代理时（Ref 或 Computed），回调参数是 `origin.value` 的值，而非源对象的克隆。

### watchPropsChange()

`watchPropsChange()` 函数用于监听响应式对象的多个指定属性的变化。

```js
import { watchPropsChange, reactive } from 'vitarx'

const user = reactive({ name: 'Alice', age: 25, role: 'admin' })

// 监听多个指定属性
watchPropsChange(user, ['name', 'age'], (props, origin) => {
  console.log(`属性 ${props.join(', ')} 发生了变化`)
})

// 只有指定的属性变化才会触发回调
user.name = 'Bob'
// 输出: 属性 name 发生了变化
user.role = 'user'
// 不会触发回调，因为没有监听 role 属性
```

### watchPropChange()

`watchPropChange()` 函数用于监听响应式对象的单个指定属性的变化。

```js
import { watchPropChange, reactive } from 'vitarx'

const user = reactive({ name: 'Alice', age: 25 })

// 监听单个属性
watchPropChange(user, 'age', (props, origin) => {
  console.log(`user.${props[0]} 变为 ${origin.age}`)
})

user.age = 26
// 输出: user.age 变为 26
```

### watchPropValue()

`watchPropValue()` 函数用于监听响应式对象的某个属性值的变化，回调函数接收新值和旧值作为参数。

```js
import { watchPropValue, reactive } from 'vitarx'

const user = reactive({ name: 'Alice', age: 25 })

// 监听属性值
watchPropValue(user, 'age', (newValue, oldValue) => {
  console.log(`年龄从 ${oldValue} 变为 ${newValue}`)
})

user.age = 26
// 输出: 年龄从 25 变为 26
```

### watchDepend() / watchEffect()

`watchDepend()` 和 `watchEffect()` 是同一个函数的两个名称，它们用于监听函数内部使用的响应式数据的变化。

```js
import { watchEffect, ref } from 'vitarx'

const count = ref(0)
const name = ref('Alice')

// 自动收集依赖并监听变化
watchEffect(() => {
  console.log(`Count: ${count.value}, Name: ${name.value}`)
})
// 立即输出: Count: 0, Name: Alice

// 修改任何依赖都会触发回调
count.value++
// 输出: Count: 1, Name: Alice
name.value = 'Bob'
// 输出: Count: 1, Name: Bob
```

## 侦听器配置选项

所有侦听函数都接受一个可选的配置对象作为最后一个参数，用于自定义侦听器的行为。

```js
import { watch, reactive } from 'vitarx'

const state = reactive({ count: 0 })

watch(state, (props, origin) => {
  console.log(`属性 ${props.join(', ')} 发生了变化`)
}, {
  // 配置选项
  batch: false, // 是否批量处理变化，默认为 true
  limit: 5,     // 限制触发次数，默认为 0（无限制）
  scope: true   // 是否自动添加到当前作用域，默认为 true
})
```

### batch

`batch` 选项控制是否批量处理变化。默认为 `true`，表示在同一个事件循环中的多个变化只会触发一次回调。设置为 `false` 时，每个变化都会立即触发回调。

> 注意：设置 `batch: false` 需谨慎使用，例如监听数组时，调用 `array.splice` 等方法可能会触发多次回调。

### limit

`limit` 选项限制侦听器触发的次数。默认为 `0`，表示无限制。设置为正整数时，侦听器最多触发指定次数后会自动停止。

### scope

`scope` 选项控制侦听器是否自动添加到当前作用域。默认为 `true`，表示侦听器会随着组件的销毁而自动销毁。设置为 `false` 时，需要手动管理侦听器的生命周期。

## 停止侦听

所有侦听函数都会返回一个侦听器实例，可以调用其 `destroy()` 方法来停止侦听。

```js
import { watch, ref } from 'vitarx'

const count = ref(0)

// 创建侦听器
const listener = watch(() => count.value, (newValue, oldValue) => {
  console.log(`count 从 ${oldValue} 变为 ${newValue}`)
})

// 修改值触发侦听回调
count.value++
// 输出: count 从 0 变为 1

// 停止侦听
listener.destroy()

// 修改值不再触发回调
count.value++
// 没有输出
```

## 异步更新队列

### nextTick()

`nextTick()` 函数用于在下一个 DOM 更新周期之后执行回调函数，或者返回一个 Promise 用于等待下一个更新周期。

```js
import { nextTick, reactive } from 'vitarx'

const state = reactive({ count: 0 })

// 修改数据
state.count++

// DOM 还未更新
console.log(document.getElementById('counter').textContent) // 显示旧值

// 使用回调函数
nextTick(() => {
  // DOM 已更新
  console.log(document.getElementById('counter').textContent) // 显示新值
})

// 或者使用 async/await
async function update() {
  state.count++
  await nextTick()
  // DOM 已更新
  console.log(document.getElementById('counter').textContent) // 显示新值
}
```

## 最佳实践

### 选择合适的侦听函数

- 使用 `watch` 监听整个响应式对象或 getter 函数
- 使用 `watchChanges` 监听多个响应式对象
- 使用 `watchPropsChange` 或 `watchPropChange` 监听特定属性
- 使用 `watchValue` 或 `watchPropValue` 获取新旧值比较
- 使用 `watchEffect` 自动收集依赖并监听变化

### 避免在侦听回调中修改被侦听的数据

在侦听回调中修改被侦听的数据，可能会导致无限循环。如果需要在回调中修改数据，请确保有条件限制，避免无限递归。

```js
// 错误示例 - 可能导致无限循环
watch(() => count.value, (newValue) => {
  // 在回调中修改被侦听的数据
  count.value++
})

// 正确示例 - 有条件限制
watch(() => count.value, (newValue) => {
  if (newValue < 10) {
    count.value++
  }
})
```

### 使用批处理优化性能

当需要监听多个数据源或频繁变化的数据时，使用批处理可以优化性能，避免过多的回调执行。

```js
import { watchChanges, reactive, ref, microTaskDebouncedCallback } from 'vitarx'

const user = reactive({ name: 'Alice', age: 25 })
const settings = ref({ theme: 'dark' })

// 使用微任务防抖函数实现批处理
watchChanges([user, settings], microTaskDebouncedCallback(() => {
  // 在同一个微任务中只执行一次
  console.log('数据已更新，执行相关操作')
}))
```
